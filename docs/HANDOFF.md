## ۱. هدف پروژه
بازی سه‌بعدی Low Poly، فارسی، آفلاین، اندروید (Unity `6000.3.11f1`). کودک در هر مرحله یک حرفه را **واقعاً تجربه می‌کند و یاد می‌گیرد**، و ما از رفتار واقعی او در بازی می‌فهمیم به کدام نوع فعالیت گرایش بیشتری دارد (فقط نشانهٔ تقریبیِ درون بازی؛ نه ارزیابی علمی/روان‌شناختی، نه برچسب شغلی).

۱۰ حرفه × ۵ مأموریت = ۵۰: معلم، مهندس و سازنده، پزشک، محیط‌بان و بازیافت، کشاورز، آتش‌نشان، راننده و حمل‌ونقل، دامپزشک، فروشنده، مهندس فناوری.

## ۳. ریپو، CI و گردش کار
- ریپو: `https://github.com/ghadirb/my-future-city`
- workflowها (`.github/workflows`):
  - `validate.yml` — اعتبارسنج بدون Unity (سریع)
  - `unity-tests.yml` — تست EditMode (~۸–۱۰ دقیقه؛ روی PR هم اجرا می‌شود، با کمی تأخیر پس از ساخت PR)
  - `build-android.yml` — فقط روی push به `main`؛ APK می‌سازد و در Release با تگ **`latest-apk`** (فایل `MyFutureCity.apk`) منتشر می‌کند (~۱۵–۲۰ دقیقه)
- Secretها (قبلاً تنظیم شده): `UNITY_LICENSE`، `UNITY_EMAIL`، `UNITY_PASSWORD`.
- ریپو باید public بماند تا CI کار کند.

گردش کار:
1. clone با توکن موقت و **بلافاصله برگرداندن remote به URL بدون توکن**: `git remote set-url origin https://github.com/ghadirb/my-future-city.git`. برای push از `git push "https://x-access-token:$TOKEN@github.com/ghadirb/my-future-city.git" <branch>` استفاده کن تا توکن در remote نماند.
2. **شاخه را همیشه از `origin/main` تازه جدا کن** (`git fetch` سپس `git checkout -B feat/<n> origin/main`). در نشست قبل شاخه را به‌اشتباه از شاخهٔ پیشین (پیش از squash) جدا کردم و PR با `main` تعارض (`mergeable_state: dirty`) پیدا کرد؛ با cherry-pick روی `origin/main` درست شد. پس از ساخت PR مقدار `mergeable_state` را بررسی کن (`dirty` = تعارض).
3. PR با API (`POST /repos/ghadirb/my-future-city/pulls`) → صبر برای سبز شدن `Validate` و `Unity tests`
4. squash-merge (`PUT /pulls/<n>/merge`) → `Build Android` خودکار روی main
5. APK: `https://github.com/ghadirb/my-future-city/releases/tag/latest-apk`
6. به‌روزرسانی `docs/PROGRESS.md` و `docs/REAL_WORK_STATUS.md` با تفکیک اثبات‌شده/اثبات‌نشده

نکته‌ها:
- دستورها محدودیت زمانی دارند؛ CI را با چند poll کوتاه (`sleep` حدود ۲۸ ثانیه، حداکثر ~۹ دور در هر فراخوانی) دنبال کن.
- تست‌های منطقی بدون Unity: `apt-get install -y mono-mcs` (**بدون `sudo`**؛ در محیط نشست قبل `sudo` وجود نداشت) سپس `./tools/run-logic-tests.sh`.

## ۵. معماری و فایل‌های کلیدی
```
Assets/_Game/
  Scripts/Core/      منطق خالص C# (بدون Unity)، قابل تست با Mono
  Scripts/Runtime/   MonoBehaviourها: بازیکن، دوربین، تعامل، HUD، منو، ذخیره
  Scripts/Editor/    SceneGenerator، ProjectValidator، BuildScript
  Resources/Data/    missions.json، activities.json (داده‌محور)
  Resources/Fonts/   Vazirmatn-Regular.ttf
  Tests/EditMode/    تست‌های Unity و منطق
tools/               validate_repo.py، audit_real_work.py، typecheck-unity-code.sh، run-logic-tests.sh
docs/                ARCHITECTURE، PROGRESS، REAL_WORK_STATUS، TEST_PLAN، BUILD_ANDROID، HANDOFF، ...
```
- `Core/MissionService.cs` — اجرای مأموریت (پاداش کامل فقط بار اول؛ تکرار فقط `repeatCoins`)
- `Core/ActivityData.cs` — مدل فعالیت + اعتبارسنج (شامل `ActivityStep.ordered`)
- `Core/ActivityService.cs` — `ActivitySession` (انتخاب‌ها، `Place`/ترتیب در `Choose`، راهنما، رها کردن) و ثبت لاگ علاقه
- `Core/InterestAnalyzer.cs` — گزارش علاقه از لاگ واقعی (مشارکت، موفقیت، تکرار، انتخاب آزاد جدا از هم)
- `Core/SaveData.cs` — ذخیره (نسخهٔ ۳، `Sanitize()`، `choiceTags`)
- `Runtime/ActivityInteractable.cs` — نمایش گام‌ها در دیالوگ (شامل `ShowOrderedStep`)
- `Editor/SceneGenerator.cs` — صحنه‌ها هر بار از نو ساخته می‌شوند

### ساختار داده
- `missions.json`: `jobs[]`، `buildings[]`، `missions[]` (هدف‌ها: `collect | interact | talk`).
- `activities.json`: هر فعالیت برای یک هدف `interact`: `realWorldFa` / `childDoesFa` / `skillFa`، `scenes[]` (نقطهٔ N ام ← صحنهٔ N ام)، `variants[]` اختیاری `{tag:"key=value", scenes[]}`.
- قواعد اعتبارسنج (هم C# هم `tools/validate_repo.py`، باید هماهنگ بمانند):
  - هر step عادی ۲ یا ۳ گزینه با بازخورد دوستانه؛ حداقل یک درست و یک غلط و `hintFa`.
  - step آزاد (`free:true`): همهٔ گزینه‌ها پذیرفته و فقط به‌عنوان علاقه ثبت می‌شوند.
  - step ترتیبی (`ordered:true`): ۳ یا ۴ آیتم، **به ترتیب درست نوشته می‌شوند**؛ `textFa` = آیتم، `feedbackFa` = چرا اینجا می‌آید؛ `hintFa` لازم؛ `free` نباشد؛ `correct` نادیده گرفته می‌شود (همه را `true` بگذار).
  - `setsTag` به شکل `key=value`؛ تگ هر variant باید جایی در همان حرفه ست شود؛ هر variant دست‌کم به‌اندازهٔ `count` هدف صحنه دارد.
- کلید لاگ صحنهٔ variant: `100*(variantIndex+1)+sceneIndex`.
- ذخیره: `persistentDataPath/save.json` + پشتیبان؛ لاگ علاقه جدا از `coins/xp`.

### الگوی تست
- حل‌کننده‌های تست (`Solve`، `SolvePreferringTag`) باید `session.NextAcceptedIndex()` را بگیرند و پاسخ را با `r.Accepted || r.Placed` بسنجند (گام ترتیبی چند بار `Placed` برمی‌گرداند و فقط آیتم آخر `Accepted`). `session.WrongIndex()` یک گزینهٔ نادرست می‌دهد (ممکن است `-1` باشد: روی آیتم آخر ترتیبی غلطی وجود ندارد).
- یک گام ترتیبی در آمار «یک تصمیم» حساب می‌شود، نه به‌ازای هر آیتم؛ هر جایگذاری در لاگ هست.

## ۶. تله‌ها (حتماً بخوان)
1. در کد Runtime هرگز `GameObject.CreatePrimitive` نگذار (در بیلد دستگاه `SphereCollider` حذف می‌شود و خطای قرمز می‌دهد). مش را در کد بساز.
2. `PlayerSettings.stripEngineCode = false` عمداً؛ `link.xml` فقط اسمبلی‌های بازی را نگه می‌دارد.
3. هر متن فارسی باید از `PersianShaper` رد شود (اتصال حروف، لام‌الف، RTL، ارقام فارسی)؛ Wrap فارسی تقریبی است. هر متن/دکمهٔ جدید را روی گوشی چک کن. در دیالوگ ترتیب‌دهی شمارهٔ آیتم‌ها با رقم لاتین و پرانتز نوشته می‌شود و احتمالاً روی گوشی باید بررسی شود.
4. دیالوگ‌های بلند در `ScrollRect` هستند؛ دکمه‌ها باید زیر متن بمانند.
5. صحنه‌ها و متریال‌ها در گیت نیستند؛ `SceneGenerator` می‌سازدشان.
6. Render pipeline: Built-in با `Unlit/Color`. URP خارج از برنامه است.
7. APK باید ARMv7 + ARM64 + x86_64 باشد؛ بدون مجوز اندرویدی (آفلاین).
8. نسخهٔ Unity در `ProjectSettings/ProjectVersion.txt` و workflowها یکسان بماند.
9. `mcs` نحو قدیمی‌تر C# دارد؛ اگر type-check روی نحو جدید خطا داد، ساده‌تر بنویس. type-check فقط `Core` را می‌سنجد؛ کد `Runtime` را فقط CI (Unity) کامپایل می‌کند.
10. فایل تست با نام شامل `Json` در Mono اجرا نمی‌شود (فقط در CI). `NUnitShim` فقط بخشی از NUnit را دارد.
11. قبل از merge منتظر CI سبز بمان؛ وضعیت `mergeable_state` را هم ببین.
12. `docs/HANDOFF.md` داخل ریپو قدیمی است؛ این سند جایگزین آن است.
